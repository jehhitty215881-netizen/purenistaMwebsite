# 這版：把所有複製功能查了一遍

網站有三個地方會複製到剪貼簿。查下來**你寫的那個是對的，我寫的兩個都有 bug**。

## 三個 bug，都在我寫的部分

| 問題 | 後果 |
|---|---|
| `.catch(function(){})` 空的 | 失敗了直接吞掉，不告訴使用者 |
| 提示寫在 `then()` **外面** | **不管成不成功，都顯示「已複製」** |
| 沒有 `execCommand` 備援 | 非 HTTPS 或舊瀏覽器完全不能複製 |

最糟的是這三個加起來：**複製失敗 → 按鈕說「已複製」→ 使用者去貼上發現是空的**。

而且 `navigator.clipboard` **需要安全連線才存在**——所以只要有人把檔案下載下來
用瀏覽器直接開，複製就是全部失效，而畫面還一直說成功。

## 改法：照你那個寫法統一

你的角色隨機生成三件事都做對了（有備援、有失敗提示、成功才報成功），
所以我把它抽成共用函式，三個地方都改用它：

```
標題／標籤複製  →  __zjkCopy
工作台企劃卡    →  __zjkCopy
角色隨機生成    →  __zjkCopy
```

現在的行為：

1. 有 `navigator.clipboard` 就用它
2. **失敗或不存在時，自動退回 `execCommand`**（含 iOS 需要的 `setSelectionRange`）
3. 兩種都失敗才顯示「**複製失敗，請長按選取**」
4. 確認訊息只在**寫入真的完成之後**才出現

## 順手修的第四個

連續點兩次複製鈕的話，第二次會把「已複製」**當成按鈕原本的文字記下來**，
於是文字永遠回不去了。現在會先取消前一次的計時器再處理。

## 測試

11 項，模擬各種實際會遇到的情況：

| 情境 | 結果 |
|---|---|
| 正常（有 clipboard API） | 複製成功 |
| 非 HTTPS／舊瀏覽器（無 API） | 自動退回 execCommand ✓ |
| 使用者拒絕權限（promise reject） | 改走 execCommand ✓ |
| 兩種都失敗 | **不會謊稱成功** ✓ |
| 空內容 | 走失敗分支 |
| 暫存 textarea | 有正確移除 |
| 連點兩次 | 文字不會卡住 ✓ |
