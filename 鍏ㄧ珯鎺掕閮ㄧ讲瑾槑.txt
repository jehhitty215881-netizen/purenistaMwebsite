功能熱門排行 — 說明
====================

網站有「我的 / 全站」雙排行，兩個都不用設定就能用。

- 我的：本機 localStorage，只有這台裝置看得到
- 全站：所有訪客共用，走 counterapi（網站本來就在用的免費計數服務）

全站排行＝開箱即用
------------------
不用註冊、不用金鑰、不用部署。程式裡已經寫好，切到「全站」就會顯示。
用的是和瀏覽次數、比例試算、配色靈感同一個命名空間（tourmaline8b7d78），
每個分頁一支計數，key 名稱是 feat-<分頁ID>，例如 feat-calc、feat-check。

隱私
----
- 只送出分頁 ID，不含帳號、IP 或任何識別碼
- 同一瀏覽器同一分頁 60 秒內只計一次
- 計數是公開的：知道命名空間的人都查得到數字（counterapi v1 的特性）

限制
----
counterapi 每分鐘 30 次請求，且「各條網址各自計算」。
22 個分頁是 22 條網址，讀一次完整排行對每條只花一次，正常使用不會踩到。

改用自己的 Cloudflare Worker
----------------------------
好處：讀取從 22 次請求變成 1 次；資料存在自己手上；沒有公開查詢的問題。
代價：要花五分鐘設定。等哪天真的熱門到 counterapi 撐不住再考慮就好。

為什麼是 D1 而不是 KV
- 更早的版本把所有計數放在同一個 KV key，用「讀出來 → +1 → 寫回去」累加。
  KV 沒有原子加法，兩個人同時點會少算一次；同一個 key 每秒只能寫一次；
  免費方案每天只有 1,000 次寫入，用完當天就靜靜停止計數。
- D1（免費的 SQLite）一行 SQL 原子遞增，每天 10 萬次寫入。

步驟
1. 註冊 https://dash.cloudflare.com（免費）
2. Storage & Databases → D1 → Create database（名稱隨意）
3. 進入該資料庫 → Console，執行：

     CREATE TABLE IF NOT EXISTS hits (
       tab TEXT PRIMARY KEY,
       n   INTEGER NOT NULL DEFAULT 0
     );

4. Workers & Pages → Create Worker → 貼上同包內 cloudflare-rank-worker.js → Deploy
5. Settings → Bindings → Add → D1 database
   - Variable name: DB
   - 選第 2 步建立的資料庫
6. 再 Deploy 一次，複製 Worker 網址
7. 編輯 index.html 與 en.html，搜尋：
     var GLOBAL_RANK_ENDPOINT = '';
   改成你的網址。填了之後就會自動改走 Worker，不再使用 counterapi。
8. 推送回 GitHub Pages

若顯示讀取失敗，最常見的原因是第 3 步的建表 SQL 沒有執行。
Worker 檔案開頭有 ORIGINS 陣列，填入你的網域可以擋掉瀏覽器以外的來源。
